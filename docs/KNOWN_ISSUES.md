# Smart Inventory — Known Issues & Gotchas

> **For AI agents:** Read this before making changes. These are non-obvious behaviors and common pitfalls.

---

## ⚠️ Critical Gotchas

### 1. SVG Canvas is 3200×2500, NOT 3200×2000
The warehouse SVG canvas height is **2500**, not 2000. This is defined in:
- `backend/services/route_planner.js` → `LAYOUT.CANVAS_H = 2500`
- `backend/services/svg_generator.py` → canvas generation

**Any component that fits the SVG to a container must use 2500 as the height.**
Files that hardcode this: `WarehouseSVGViewer.jsx`, `WorkerDashboard.jsx`.

### 2. Routing Direction: DISPATCH → ENTRANCE
Routes start at **DISPATCH** (right wall, x=3080) and end at **ENTRANCE** (left wall, x=120).
- DISPATCH = **Entry Gate** (where workers enter)
- ENTRANCE = **Exit Gate** (where workers exit)

The naming is historically confusing — DISPATCH/ENTRANCE are internal graph node IDs, not physical labels.

### 3. JSON File Store — No Concurrent Write Safety
`jsonStore.js` reads/writes JSON files with no locking. If two requests write simultaneously, data loss can occur. The `congestion_control.js` uses `fs.renameSync` for atomic writes, but the main store does not.

### 4. `window._currentWorkerTasks` Global
`WorkerDashboard.jsx` stores active tasks on `window._currentWorkerTasks` for cross-function access (route drawing, slot highlighting). This is a global mutable state — be careful when modifying.

### 5. Worker Position Default: (80, 960)
All workers default to position `(80, 960)` — near the ENTRANCE gate. This is set in:
- `server.js` → `migrateWorkers()`
- `POST /api/reset-warehouse`

### 6. Task Cleanup Runs on EVERY Request
`server.js` runs `cleanupStaleTasks()` as middleware on every incoming request. This means every API call triggers a scan of all tasks for stale ones. Not ideal for performance at scale.

## 🔧 Common Issues

### SVG Not Rendering
- Check that `warehouse_allocated.svg` exists in `frontend/svgs/`
- It's regenerated by `regenerateSVG()` after slot allocation changes
- Frontend fetches it as `/svgs/warehouse_allocated.svg?t=<timestamp>`

### Route Has No aisle_path Data
- Check that `getSlotAccessNode()` found a valid node for each slot
- If a slot's coordinates are far from any walking aisle, it maps to `null`
- `findNearestNonTerminalNode()` is the fallback

### Worker Login Fails
- Workers must have `is_active: true` in `workers.json`
- Password comparison is plaintext: `worker.password !== password`
- Default password: `warehouse123`

### Congestion Control Not Working
- Requires `workers.json` with `position_x/position_y` fields
- Workers must have `status: 'Busy'`
- Aisle segments are hardcoded in `route_planner.js` → `AISLE_SEGMENTS`

### Python Scripts Failing
- `cart_clusterer.py` and `slot_allocator.py` use stdin/stdout for data
- Requires `python` (not `python3`) on PATH — Windows compatibility
- Dependencies: `numpy`, `scikit-learn`

## 🔄 Reset Procedure

To fully reset the warehouse to a clean state:

1. Use the admin dashboard "Reset Warehouse" button, OR
2. Call `POST /api/reset-warehouse` (requires JWT)

This will:
- Clear all slot occupancy
- Reset all workers to Available at position (80, 960)
- Clear all tasks, cart groups
- Reset all carts to available
- Regenerate empty SVG
